# 《基于Web的在线协作黑板与文件实时批注系统》开题报告大纲

## 一、 课题背景与痛点（提出问题）

- **背景**：线上小组学习、远程讨论已成常态，但现有工具（白板、语音软件、网盘）相互割裂。

- **核心痛点**：
  
  - 沟通上下文断裂：语音在A软件，画图在B软件，文件在C软件，切换繁琐。
  
  - 文件讨论难同步：在文档上圈画批注，无法实时同步给其他人看。
  
  - 缺乏轻量化方案：复杂的局域网配置或客户端安装门槛太高。

- **课题定位**：打造一个**纯公网、零配置、开箱即用**的Web协作空间，将“文件批注 + 协同白板 + 语音交流”融为一体。

## 二、 研究目标与核心功能（解决痛点）

- **核心定位**：以文件/资料为中心的“在线黑板”。

- **MVP（最小可行性产品）功能**：
  
  1. **文件上传与实时批注**：上传PDF/图片，多人可在同一份文件上圈画、写便签，批注实时同步。
  
  2. **多人协同白板**：提供空白画布，支持多人同时绘图、光标同步。
  
  3. **实时语音聊天室**：在协作的同时进行语音讨论。
  
  4. **文字聊天**：辅助发送链接、文字资料。

## 三、 技术实现方案

*(本部分是开题核心，需要说明用什么技术实现什么功能，通俗易懂即可)*

- **1. 整体架构（纯公网B/S架构）**
  
  - 用户只需浏览器即可访问，所有数据经公网服务器同步，无需任何局域网配置。

- **2. 协同白板与文件批注同步（WebSocket + CRDT）**
  
  - **通信协议**：采用 **WebSocket** 保持长连接，实现双向实时消息推送。
  
  - **同步引擎（核心难点）**：引入 **CRDT（无冲突复制数据类型）** 算法（如 Yjs 库）。解决多人同时画图、同时批注同一个区域时的冲突问题，确保画面不覆盖、不卡顿。
  
  - **文件批注实现**：前端将上传的PDF/图片转为可覆盖的“虚拟图层”，批注数据（坐标、内容）结构化后通过WebSocket广播，所有客户端实时渲染出相同的批注。

- **3. 语音聊天室（WebRTC）**
  
  - **信令控制**：通过WebSocket交换连接信息。
  
  - **媒体传输**：使用 **WebRTC** 进行P2P语音传输（小房间采用Mesh架构）。
  
  - **连通保障**：部署 **Coturn** 服务器作为STUN/TURN，解决不同公网环境下的NAT穿透问题，确保语音100%连通。

- **4. 关键技术难点**
  
  - 多人并发批注时的状态一致性（通过CRDT算法解决）。
  
  - 高频白板操作带来的公网带宽压力（通过前端节流与增量同步解决）。
