# 《基于Web的协同白板与实时音视频及局域网快传系统》开题报告大纲

## 一、 提出问题（研究背景与意义）

- **1.1 研究背景**
  
  - 线上/混合式学习与宿舍讨论的常态化。
  
  - 现有工具的碎片化：白板（如Miro）、语音（如腾讯会议/Discord）、文件传输（如微信/网盘）各自独立，切换频繁，割裂了协作体验。

- **1.2 核心问题**
  
  - 如何在轻量级Web环境下，实现低延迟的“白板+语音+文件”三位一体协同？
  
  - 在局域网（宿舍/教室）环境下，如何突破公网带宽限制，实现极速文件共享？

- **1.3 研究目标**
  
  - 构建一个无需安装客户端、基于浏览器即可使用的协同空间。
  
  - 实现操作同步延迟低于100ms，语音通话清晰，局域网文件传输速度跑满带宽。

## 二、 解决痛点（需求分析与场景定位）

- **2.1 目标场景**
  
  - **小组学习/项目讨论**：需要实时画图推导、同步讲解、分享资料。
  
  - **宿舍局域协作**：在带宽受限或外网不佳时，依赖局域网进行高效资料分发。

- **2.2 现有痛点**
  
  - **操作割裂**：语音时无法直观看到对方在画什么，画图时又要挂断语音。
  
  - **文件传输慢**：公网网盘中转慢，且受限于服务器带宽；大文件（如视频、数据集）分享体验差。
  
  - **并发与同步冲突**：多人同时绘图时容易出现光标漂移、画板覆盖、状态不一致。

- **2.3 本课题的解决方案**
  
  - 三位一体：白板（视觉）+ 语音（听觉）+ 文件（资料）在同一页面无缝集成。
  
  - 局域网P2P/局域网直连：优先局域网快传，保证大文件传输速度。

## 三、 技术实现（核心内容细化）

*(此部分为重点，根据图片中的协议与MVP进行细化展开)*

- **3.1 系统整体架构设计**
  
  - **前端**：HTML5 Canvas / SVG（白板），WebRTC API（语音），Fetch/Axios（文件上传）。
  
  - **后端**：Node.js / Go 作为信令服务器与HTTP文件服务。
  
  - **通信层**：WebSocket（信令与状态同步）+ WebRTC（媒体流）+ HTTP（文件流）。

- **3.2 模块一：协同白板与光标同步（基于WebSocket）**
  
  - **通信协议设计**：自定义WebSocket消息格式（JSON），区分事件类型（Draw, Erase, CursorMove, Undo）。
  
  - **操作同步机制**：
    
    - 采用**操作转换（OT）**或**CRDT（无冲突复制数据类型）**算法解决多端并发绘图冲突。
    
    - 全量同步与增量同步结合：新用户加入时下发全量画板状态（历史操作序列），之后仅广播增量操作包。
  
  - **光标同步**：高频发送鼠标坐标，前端进行插值与平滑处理，避免光标“瞬移”。
  
  - **文字聊天室**：复用WebSocket通道，实现群组文本消息的实时收发与历史记录存储。

- **3.3 模块二：语音聊天室（基于WebRTC）**
  
  - **信令控制**：利用WebSocket完成SDP交换与ICE候选者交换。
  
  - **拓扑结构选型**：针对“小组/宿舍”场景（人数通常<10人），采用**Mesh网状架构**（P2P直连），降低服务器负载与延迟。
  
  - **音频处理**：开启WebRTC自带的回声消除（AEC）、噪声抑制（NS）和自动增益控制（AGC）。

- **3.4 模块三：文件传输（HTTP + 局域网快传）**
  
  - **基础文件上传**：基于HTTP POST，支持多文件上传、进度条显示、断点续传（分片上传）。
  
  - **局域网快传优化（核心亮点）**：
    
    - 利用WebRTC的DataChannel进行P2P文件传输（若在同一局域网，数据不经过公网服务器）。
    
    - 或采用UDP广播/mDNS进行局域网节点发现，建立局域网HTTP直传通道，最大化利用内网带宽。

- **3.5 关键技术难点与解决方案**
  
  - **难点1**：WebSocket高频消息导致服务器带宽压力。
  
  - **对策**：消息节流（Throttling）、坐标压缩、二进制协议（如Protobuf）替代JSON。
  
  - **难点2**：NAT穿透失败导致WebRTC无法连接。
  
  - **对策**：部署STUN/TURN服务器（如Coturn）作为降级方案。

## 四、 实验设计与性能评估

*(根据图片中的“实验”要求展开)*

- **4.1 实验环境搭建**
  
  - 局域网环境（千兆/百兆路由器）、公网环境（4G/5G/Wi-Fi）。
  
  - 测试终端：PC浏览器（Chrome/Edge）、移动端浏览器。

- **4.2 实验指标与测试方法**
  
  - **操作同步延迟**：使用高精度时间戳，测量从A端发送绘图指令到B端渲染完成的时间差（目标：<100ms）。
  
  - **并发人数**：压力测试，逐步增加白板/语音房间的并发用户数（如5人、10人、20人），观察CPU占用率与消息丢失率。
  
  - **文件传输速度**：对比“公网HTTP中转”与“局域网P2P/直传”在100MB/1GB文件下的传输耗时与平均速率。

- **4.3 预期结果**
  
  - 实现MVP（多人绘图、光标同步、语音、资料上传）功能全覆盖。
  
  - 局域网文件传输速度达到物理带宽上限的80%以上。

- **第二阶段：核心模块开发（第3-6周）**

  - Week 5-6：集成WebRTC语音通话，实现HTTP文件上传与进度反馈。

- **第三阶段：局域网快传与系统集成（第7-8周）**
  
  - 实现局域网节点发现与P2P文件传输优化。
  
  - 前后端联调，完成三位一体集成。

- **第四阶段：性能测试与优化（第9-10周）**
  
  - 执行同步延迟、并发压力、传输速度实验。
  
  - 针对高并发下的丢包、延迟问题进行算法与架构调优。

- **第五阶段：报告撰写与答辩准备（第11-12周）**
  
  - 整理实验数据，撰写结题报告与项目文档，录制演示视频。
